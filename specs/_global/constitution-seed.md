## Recommended Development Principles

### Test-First
Write tests before implementation. For this library, test chart rendering output at the character level.

### Think Before Coding
Understand the ASCII rendering algorithms before implementing. Consider terminal width constraints.

### Simplicity First
Keep chart algorithms simple. Use basic block characters for rendering.

### Surgical Changes
Make incremental changes. Each chart type can be developed independently.

### Goal-Driven Delivery
Each Feature should produce a working chart type that can be demonstrated.

### Demo-Ready Delivery
Every completed Feature should be runnable — `npm run start` should produce visible output.

## Project-Specific Principles

### Domain-Driven

- **ASCII-first design**: All charts render as text, no pixel graphics
- **Terminal-native**: Charts respect terminal dimensions via Terminal.width/height

### Architecture-Driven

- **Config-driven charts**: Each chart type has typed config and options
- **Separation of concerns**: Chart logic (F003), utilities (F002), types (F001)

### Scale-Driven

- **Micro project**: Simplified pipeline, minimal ceremony
- **Single package**: No monorepo, straightforward build

### Quality-Driven

- **Type safety**: ReScript provides strong typing
- **Validation**: ChartValidation ensures option correctness
- **Error handling**: CLI adapter provides descriptive error messages
